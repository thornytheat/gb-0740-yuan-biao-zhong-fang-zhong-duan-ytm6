# 编码切换准入终端

区域编码上线后，同一订单分区并存新旧两套键名。值班组据来源快照、键映射证据、旧键对照留存与已交付指针生成切换准入：哪些来源已能独立交付、哪些还需旧键对照、哪些因映射证据不全不能放行，并圈定未切换范围。发布、回查、补数读取同一份准入；切换失败时已交付结果按锚点回退到原区域。页面只读展示准入与未切换范围，不做权限或批量运营。

## 启动与演练

运行 `docker compose up --build -d`，访问 `http://127.0.0.1:18429/`。

1. 打开「订单编码切换」。在准入总览筛到「不可放行」，查看 west（映射冲突）、central（对照丢失）、northeast（锚点断链）的证据缺口。
2. 切换「单源演练」，点击「生成准入」。`east` 判为独立交付，回退演练恢复一致。
3. 转到「三务口径」。发布、回查、补数三表同读一个准入编号；`central` 已切换区域显示「无法复核」。
4. 下载一份准入文档交接，含覆盖范围、未切换范围、映射证据与回退摘要。

`POST /api/admissions` 接收 `{"sample":"cutover"}` 或表单的 `bundle` JSON 文件。`GET /api/publish/<编号>`、`/api/recheck/<编号>`、`/api/backfill/<编号>` 供三务读取同一准入。模块及字段说明见 [深度登记](docs/DEPTH.md) 和 [数据字典](docs/DATA-DICTIONARY.md)。

运行 `docker compose exec -T app pytest -q` 复核。`docker compose down` 停止应用并保留签发历史。
